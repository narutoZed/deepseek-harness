# Agent Note: SDK 审批与后代控制

Status: implemented

[English](2026-09-10-sdk-approval-and-descendant-controls.md) | 中文

## Problem

SDK 宿主需要回复待处理的权限问题，并控制指定子会话而不取消整个运行时。用新的根会话替代子会话会丢失原生历史及父会话归属。

## Decision

SDK 服务器只转发属于 SDK 根会话及其后代的原生审批请求。每条回复消费一个绑定到会话的待处理问题，仅允许一次或拒绝操作。中止和关闭会结算待处理问题，不授予访问权限。

按地址发送子会话提示词和中断使用原生子代理服务。服务器检查持久化的根会话祖先关系、直接父会话身份和可续聊模式。原生冷启动续聊恢复同一个子会话；其直接父会话必须存活，SDK 根会话可以从持久化记录重新打开。组合缺少所需服务时，能力标记允许宿主禁用控制。

## Alternatives considered

**由宿主创建替代会话。** 新会话会切断子会话身份、历史及原生父会话归属，因此续聊保留已记录的原生子会话。

**通过取消整个运行时中断子会话。** 关闭进程也会停止父会话及兄弟会话。按地址操作将取消委托给原生子会话运行时。

**用永久权限更新代替审批。** 更新策略会授权用户尚未审核的后续操作。审批仅以单次授权结算原始请求。

## Consequences

可信宿主仍负责用户认证、外部会话授权和持久化请求回执。SDK 只在同一个进程内保存成功或进行中的子会话提示词回执。一次性子会话仍可通过宿主投影读取，但不能通过这些控制续聊。测试覆盖精确归属、已消费的问题、重复提示词和资源释放；组合后的 SDK 运行时支持宿主层的审批以及运行中和冷启动续聊测试，无需修改 agent loop。
